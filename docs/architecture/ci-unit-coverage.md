# Unit coverage contract

The CI unit matrix is the only place that executes the unit-test corpus. Each shard records the standard Vitest V8 coverage map once. `BODYCAST_INCLUDE_MODULE_COVERAGE=1` adds the Stage 1C roots from `tests/refactor-comparator/module-coverage-v1.json` to the established include scope; both the global and module checks consume the resulting merged `coverage/coverage-summary.json`.

The coverage merge job does not execute tests. Vitest merges the shard blobs, then `scripts/refactor/run-module-coverage-gate.mjs` checks the existing global floors (lines 85%, functions 85%, statements 85%, branches 80%) over the original include scope and the frozen per-file floors over Stage 1C roots. New executable module files must meet 85/85/85/80. A missing summary, missing total metric, missing expected file, or missing module measurement fails closed.

The source inventory and per-file counters are bound to `baselineSha`. The old per-file floors came from an AST-aware related-test measurement and were not comparable to the standard V8 shard report. The one-time method migration therefore replaces those counters with the complete merged V8 report from exact baseline SHA `c4642d09d8873072d5e5a62a25ac7d0985970179`; the product files under the measured roots are byte-identical between `a5a9c949089d56002bd9f9cac3a9deb30c058900` and `c4642d0`. This is a new baseline for the new measurement, not a claim of equivalence to the old counters. It adopts the already-current main source: for example, `src/modules/training/training.repository.ts` changed after original baseline `5194fcd00544f7ca94fca4fbac039f647cb26503`. Global floors remain unchanged. New executable module files still require 85/85/85/80. Coverage-excluded compatibility barrels, DTO-only files, and test helpers remain listed with reasons and cannot change without an explicit coverage review. Coverage scope and threshold constants are shared by Vitest and the gate in `scripts/refactor/coverage-scopes.mjs` and the manifest, rather than copied into CI commands.

The next exact-SHA CI run is the acceptance gate for this method update. It must pass complete unit shards without test exclusions, merge their uploaded reports, reproduce the `c4642d0` per-file V8 counters, and pass the unchanged global floors plus the newly frozen per-file V8 floors from the single merged summary. The previous CI failure is why the new measurement baseline was adopted; do not modify its floors after seeing the next report to obtain a pass. Missing paths, zero line/statement observations, or missing metric totals fail closed.

The next queued task is to revalidate Phase 1A–1C against current `main` and then continue the owner-approved architecture plan. It begins only after the current CI optimization and production-release goal is complete.

The method changed from a separate AST-aware `vitest related` run to the existing unit-shard V8 report. This is an intentional one-time Stage 1C measurement-baseline replacement. Future changes compare to the V8 counters bound to the exact accepted baseline SHA; they do not rerun the corpus or use fingerprints to validate report determinism.
