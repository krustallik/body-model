# Prospective forecast validation

Historical forecasts were not retained when they were issued. Retrospective replay can diagnose model state and reproduce saved outputs, but it cannot establish what a user would have seen at an earlier date. Historical posterior fit must not be described as future forecast accuracy.

Rolling-origin reconstructions may score only when every input is proven available by that origin's receipt-time cutoff. Label the score with the exact replay path used; do not call it an as-issued forecast or a V7 score unless the exact deployed V7 runtime and its then-current source versions were replayed. Nearby rolling origins also share observations and are not independent samples.

## Model and assimilation boundaries

An initialization that reconstructs the observed scale total exactly has not thereby validated its fat, lean, fluid, or glycogen allocation. If the initializer assigns an unobserved residual to lean tissue, temporary scale mass can be represented as tissue without independent evidence. Scale observations alone do not identify which compartment should absorb that residual. Hypothetical reallocations change downstream energy accounting, but do not establish a biologically valid assignment. Do not change physiology unless independent evidence and prospective evaluation support it.

The current episode initializer makes this limitation concrete: a selected BIA supplies weight and estimated fat percentage; fat mass follows that percentage, ECF is estimated from demographic inputs and weight, glycogen uses its configured prior, and lean tissue closes the remaining total. ECF deviation starts at zero. A one-day BIA anchor therefore allocates the whole measured total into modeled compartments even when initialization is marked `insufficient`; there is no separate unassigned-mass term for possible transient scale mass.

The authorized local retrospective `calculateEpisodeHistory` replay—not the V7 daily runtime—showed a large early scale-to-state discrepancy while modeled total changed little under the logged energy balance. This is hypothesis-generating only: it cannot distinguish an initial compartment error from transient scale mass, measurement variation, or source effects. Later residuals also remain, but do not establish accumulated energy-balance drift as their cause. A bounded ECF-only sensitivity scenario changes forecast outputs slightly but supplies no evidence that its compartment reassignment is correct. No physiology change is justified by this retrospective evidence alone.

The V7 runtime rebuilds its separate local-level observation filter from the latest immutable `HealthSyncSnapshot` per measurement date available before each profile-local day-end cutoff. A delayed or corrected snapshot can therefore change that day's and later filter states, but cannot alter an earlier cutoff. It carries uncertainty forward on days without a new weighing and changes no fat, lean tissue, glycogen, ECF, or energy-balance value. The legacy episode-calculation path also updates a local-level weight filter and reports `filteredWeightKg`.

A separate research-only as-of challenger uses the same pure filter replay with an explicit exclusive receipt-time cutoff. It permits a later-arriving measurement correction to update only that origin and later origins; it cannot alter an earlier as-of result. The local replay checks it against an independently receipt-time-prefiltered input set. V7 mass reconstruction remains unavailable, so neither path establishes an identifiable tissue trajectory. Neither filter feeds back into tissue or energy accounting. The two-timescale residual challenger is forecast-output-only and remains isolated; the small rolling-origin sample has no completed full-model forecasts and does not justify promotion. User-specific source rows, body measurements, dates, replay outputs, and derived metrics are intentionally excluded from this public repository and retained only in the authorized local forensic workspace.

## Prospective evidence contract

No API currently stores as-issued forecast outputs. The repository contains a research-only forecast payload contract, but user-facing API routes do not write snapshots. Retrospective score reports therefore remain conditional reconstructions, not as-issued accuracy.

Persistent capture is deferred: forecast snapshots contain personal weight, body-composition, and energy projections, and the owner has not set their retention or account/profile erasure policy. The 30-day HealthSyncAudit policy does not apply to them. Adding the proposed table would also raise the migration count from the supported 77 to 78, which the current migration-free Auth release gate rejects. This candidate keeps the schema at 77 migrations and does not bypass that gate. Future snapshot capture needs an owner-approved lifecycle policy, isolated schema rehearsal, separate migration handoff, and exact production DDL authorization. No production schema or data was changed during this research.

Once snapshots are authorized and enabled, evaluate each issued forecast only against observations first received after its input cutoff. Report results by origin and horizon, compare against last-known-weight and robust-trend baselines, and preserve uncertainty. Do not label historical posterior residuals or conditional replays as as-issued forecast accuracy.
